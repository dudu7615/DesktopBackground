# 移植 CallClassroom 的自动打包发布流程

日期：2026-11-20
分支：`fix/pre-release-changes`

## 目标

把 `/mnt/code/Code/CallClassroom` 的「合并进 main 自动出安装包 + 按版本号建 Release」
搬到 DesktopBackground，同时删掉原来那套本机打包器。

## 原方案为什么搬不动

| 前提 | CallClassroom | DesktopBackground 原状 |
|---|---|---|
| 打包脚本入库 | `packaging/` 全部 tracked | `.gitignore` 里 `*.spec` + `build/.gitignore` 的 `*` 把 spec 和 installer 脚本全忽略，干净克隆打不了包 |
| 依赖分组 | `[dependency-groups] build` | pyinstaller 混在 dev 里，还带 auto-py-to-exe（GUI 工具，CI 用不上） |
| 版本号 | 0.1.0 起正规化 | 0.1.0，但历史提交已到 V1.0.3，无任何 tag |
| 平台标记 | pywin32 带 `sys_platform` 判断 | pywin32 无条件依赖，Linux 上 `uv sync` 直接失败 |

## 决定

- 版本号 → `1.1.0`（首发 Release 会是 `v1.1.0`）
- exe 名 `main.exe` → `DesktopBackground.exe`，`setup.iss` 里显式清理旧 `main.exe`
- 删除 `build/`（旧打包器），新建 `packaging/`

## 改动

1. **删 `build/`**：`build.bat`、`build.iss`、`build/.gitignore`。旧 `build_installer.bat`、
   `installer.iss`、`main.spec` 本来就没入库，一并清掉（备份在 `/tmp/DesktopBackground-build-backup`）。
2. **新增 `packaging/main.spec`**：onedir，`clock/` → `dest "clock"`、`icon.ico` → `dest "."`；
   显式收集 `_ssl.pyd` 与 OpenSSL DLL；找不到时在 Windows 上打印警告。
3. **新增 `packaging/setup.iss`**：AppId 沿用旧值（升级不断链），装 `%LOCALAPPDATA%`，
   覆盖升级前 `taskkill` 新旧两个进程名。
4. **新增 `.github/workflows/release.yml`**：移植 CallClassroom 的流程，去掉了本项目
   没有的 `uv run pytest` 步骤（仓库无 tests/）。
5. **新增 `packaging/build.bat` / `build_installer.bat`**：本机打包入口，版本号从
   `pyproject.toml` 读。
6. **`pyproject.toml`**：version 1.1.0；`dev` 组去掉 auto-py-to-exe；新增 `build` 组；
   pywin32 加 `sys_platform == 'win32'` 标记。
7. **`.gitignore`**：加 `build/`、`!packaging/*.spec`。
8. **文档**：`README.md`、`packaging/README.md`、`dev/README.md`。

## 验证

- `uv lock` + `uv sync --frozen --group build` 通过，Windows wheel 齐全（含 PySide6 / pyinstaller）
- Linux 冒烟构建：`pyinstaller packaging/main.spec` 成功，冻结包实际启动、取天气、
  合成壁纸、调用 `SystemParametersInfo`，全链路走通
- `git check-ignore` 确认 `packaging/main.spec` 已入库、`build/`、`dist/` 已忽略
- workflow YAML 解析通过，12 个 step

## 未验证

- Windows runner 上的真实打包与 ISCC 编译（本地无 Windows）
- Release 创建（需要首次 push 到 main 触发）
